# SkeletonStructure v0.1.0

Release date: 2026-11-24

SkeletonStructure v0.1.0 is the first usable release of the backend foundation. It provides a modular monolith with validated configuration, PostgreSQL persistence, explicit module composition, authentication and authorization, an HTTP API, an OpenAPI-derived frontend SDK, and a complete e-commerce demonstration.

**SkeletonStructure v0.1.0 is not claimed to be completely secure or production-ready beyond the tested scope.** Careful defaults lower risk; they do not replace review, testing, and keeping your own project up to date.

## Included

- M1–M8 foundation: pnpm workspace, strict TypeScript, Biome, Vitest, CI, typed configuration, shared PostgreSQL database, module registry, Fastify API, security primitives, and ADRs.
- `users` and `auth`: Argon2id passwords, opaque SHA-256-hashed sessions, httpOnly cookies, CSRF protection, roles and permissions, ownership checks, and single-use password reset behind an `EmailProvider` port.
- `catalog`, `products`, `inventory`, and `orders`: generic catalog items, validated extensions, server-authoritative prices, optional stock reservation, idempotent orders, and immutable line snapshots.
- `@skeletonstructure/sdk`: browser-safe client generated from the committed OpenAPI contract, with cookie/bearer auth, in-memory CSRF handling, and typed errors.
- M9a e-commerce demo: Vite storefront, separate API process, app-local cart and migration, seeded products/user, checkout through order confirmation, order history, and generated demo-local client.
- M10 release work: fresh-clone setup documentation, module READMEs, threat model/security checklist, release checklist, version alignment, migration baseline statement, and this release note.

## Not included

- M9b restaurant demonstration.
- Guest checkout, payment processing, refunds, cancellations, or inventory release after confirmation.
- MFA, OAuth, CAPTCHA, real SMTP/HTTP email adapter, file uploads, webhooks, or persistent audit logging.
- Redis, shared rate limiting, multi-tenancy, additional database engines, or unrequested shared modules.
- npm publication. All packages remain private and source-distributed in v0.1.0.

## Migration compatibility

v0.1.0 is the first tagged release and establishes the database baseline. There is no earlier released schema to upgrade from.

- Supported database: PostgreSQL 16.
- Migration order: core, users, auth, catalog, products, inventory, orders; the e-commerce demo then applies one app-local cart migration.
- Fresh and repeated migrations are covered by tests; the fresh-clone check above also verified a no-op second run.
- Migrations are explicit operator actions and use an advisory lock. Production must not auto-migrate on startup.
- No destructive database change was made for v0.1.0. Backups, restore drills, and least-privilege database roles remain operator responsibilities.

## Known limitations and operator responsibilities

- Rate limiting is per process and based on IP/global limits; multi-instance deployments need a shared limiter.
- The console email adapter is development-only. A production deployment needs a reviewed real adapter and delivery monitoring.
- Reserved inventory remains reserved after order confirmation because cancellation and release are not implemented.
- There is no persistent audit log and Fastify request logging is disabled.
- The public SDK intentionally excludes demo-local cart routes.
- Operators must provide TLS, secret management, least-privilege database credentials, backups, dependency updates, monitoring, and deployment hardening.
- Role and permission assignment data must be reviewed by the application owner; roles are only as correct as their grants.

Report suspected vulnerabilities privately as described in [`../../SECURITY.md`](../../SECURITY.md).
