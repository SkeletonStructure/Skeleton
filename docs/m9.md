# M9 — Demonstration applications

M9 proves that the M1–M8 foundation can support real applications without adding domain logic to core. It is sequenced: **M9a (e-commerce)** is implemented first; M9b (restaurant) starts only after M9a acceptance has been verified.

Current repository state: **M9a is implemented. M9b is not started.**

## M9a — Complete e-commerce demonstration

The app lives in [`apps/demo-ecommerce`](../apps/demo-ecommerce). It is a Vite + vanilla TypeScript storefront plus a separate Fastify API process. The browser communicates only over HTTP; it has no database access, credentials, or server-module imports.

### Reused shared modules

| Module      | Use in the demo                                                        |
| ----------- | ---------------------------------------------------------------------- |
| `auth`      | Sessions, login/logout, CSRF tokens, and the buyer-context port        |
| `users`     | User records and the `user` role permissions                           |
| `catalog`   | Generic active items, names, slugs, descriptions, and expansion core   |
| `products`  | SKU and server-authoritative price; `expand=product` in the SDK        |
| `inventory` | Stock checks/reservations during order creation                        |
| `orders`    | Confirmed orders, immutable line snapshots, ownership, and idempotency |

### Demo-local extension

The cart is app-local at `apps/demo-ecommerce/modules/cart`. It registers `cart:read`, `cart:write`, and `cart:checkout` and exposes:

| Method   | Route                    |
| -------- | ------------------------ |
| `GET`    | `/v1/cart`               |
| `PUT`    | `/v1/cart/items/:itemId` |
| `DELETE` | `/v1/cart/items/:itemId` |
| `POST`   | `/v1/cart/checkout`      |

The cart stores no prices. It stores buyer id, catalog item id, quantity, and timestamps; names and prices are resolved server-side from `catalog` and `products`. The buyer is taken only from the authenticated session's buyer context, never from a request parameter. Cart routes are protected by authentication, declared permissions, and CSRF enforcement. Each buyer sees only their own cart.

There is no `packages/module-cart`. Shared packages and the public SDK were not changed for the demo. The app uses `createM8Composition({ additionalModules, moduleConfig })` and merges cart route handlers in its own composition file.

### User flow

1. Browse active products through `Skeleton.products.getAll()`; generated SDK types include `details.product`.
2. Log in with the seeded demo user; the SDK captures the CSRF token from the auth response and shares the session cookie.
3. Add/remove cart items through the app-local typed client.
4. Check out with a stable idempotency key. The cart service calls `orders.create()` with server-resolved line items.
5. See the confirmed order in order history through `Skeleton.orders.list()`.

### Checkout consistency

Checkout has explicit success and failure behavior:

- Validation or order-creation errors leave the cart unchanged.
- The cart is cleared only after the order is confirmed and persisted.
- The API result is `{ order, cartCleared }`. If cleanup fails after persistence, `cartCleared` is `false` and the browser keeps the idempotency key so retrying returns the same order and retries cleanup.
- A replayed key on an empty cart returns the original order when the cart's last idempotency key matches.

### Deferred payment seam

**M9a stops at order confirmation; no payment is captured or implied.** The confirmed order exposes `id`, `status`, `items`, `totalAmount`, and `currency`. A later payment capability can key a payment attempt to `order.id` and the same idempotency key. Until that capability exists:

- no browser code submits amounts to a payment processor;
- no payment provider, API key, or card data enters the demo;
- no order status beyond M8's `confirmed` is produced;
- reserved stock remains reserved because cancellation/release is also deferred.

### Contracts and generated artifacts

Shared routes continue to use `openapi/openapi.json` and `@skeletonstructure/sdk`. Demo-local cart routes use a separate artifact generated from the actual Fastify route registration:

- `apps/demo-ecommerce/openapi/demo-openapi.json`
- `apps/demo-ecommerce/src/web/demo-client.generated.ts`

Both are committed and checked for drift. The public SDK remains browser-safe and does not import demo code. The demo client is a thin `fetch` wrapper that receives the CSRF token from the SDK's auth response because the SDK keeps its own token private.

### Commands

From the repository root:

```bash
pnpm demo:ecommerce:migrate
pnpm demo:ecommerce:seed
pnpm demo:ecommerce:api
pnpm demo:ecommerce:dev
```

Seeded user (unless overridden by `DEMO_USER_EMAIL` / `DEMO_USER_PASSWORD` in the app's environment): `demo@skeletonstructure.local` / `demo-password-123`.

### Verification

```bash
pnpm demo:ecommerce:openapi:check
pnpm demo:ecommerce:client:check
pnpm demo:ecommerce:test:integration
pnpm demo:ecommerce:test:e2e
# or all four:
pnpm demo:ecommerce:verify
```

Integration coverage uses a fresh Testcontainers PostgreSQL database and verifies fresh migrations, repeated migrations, idempotent seed, authentication/CSRF on every cart route, buyer isolation, checkout failure consistency, successful clearing, and idempotent replay. Playwright drives a real browser through browse → cart management → checkout → order history against the real API process and database.

## M9b — Restaurant demonstration (not started)

M9b remains a separate, explicitly approved milestone. It should reuse `auth`, `users`, `catalog`, and `orders`, add demo-local `menu` and `branches` extensions, and prove that menu items and products stay distinct over the shared catalog core. No M9b code is included here.

## M9 limitations

Both planned demos stop at confirmation. M9a does not provide payments, guest checkout, admin tooling, order cancellation/refunds, inventory release, multi-tenancy, or production deployment configuration. M10 release work and residual limitations are recorded in [`releases/v0.1.0.md`](./releases/v0.1.0.md); M9b remains deferred.
