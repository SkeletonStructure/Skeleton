## Settings enforced now

- Active ruleset `protect-main` applies to `refs/heads/main` and blocks deletion and non-fast-forward changes while requiring pull requests. It has no bypass actors.
- The ruleset's `required_status_checks` rule exists but its list is empty and `strict_required_status_checks_policy` is false. Passing PR #7 and PR #9 checks were not enforced by this ruleset.
- The ruleset's pull-request parameters set `required_approving_review_count: 0`, `require_code_owner_review: false`, `required_review_thread_resolution: false`, `dismiss_stale_reviews_on_push: false`, and `require_last_push_approval: false`. `require_extra_approval_for_unattributed_changes` is true, but the baseline approval count is zero.
- CI workflow permissions are `contents: read`, third-party actions are SHA-pinned, and no workflow secrets are referenced.
- Secret scanning and CodeQL alert APIs were readable; all five CodeQL alerts are `fixed` and there are zero secret-scanning alerts. No alert was dismissed by this cleanup.

2. Require at least one approving review, enable code-owner review if CODEOWNERS should gate changes, dismiss stale approvals on new pushes, and require review-thread resolution or last-push approval if the owner wants those gates. All are currently disabled or zero.
